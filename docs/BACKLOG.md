# Backlog

Spor opgaver for MyCMSSolution her. Opdater status og note, når en opgave flytter sig — se `.githooks/pre-push`, som advarer, hvis kodeændringer pushes uden en tilhørende opdatering af denne fil.

**Fast regel fremover:** Enhver ny opgave får et fortløbende ID (`TASK-07`, `TASK-08` osv.) i det øjeblik den defineres — både her og i `docs/kickoff-plan-fase3-cms-mycmssolution.md`. ID'et bruges i commit-/PR-beskrivelser, så arbejdet altid kan spores tilbage til den oprindelige opgave.

| ID | Prioritet | Opgave | Status | Sprint/uge | Note |
|---|---|---|---|---|---|
| TASK-01 | Høj | Scaffold af .NET-løsningen (Web, Core, Crm.Client, SelfService, Tests) | Færdig | Uge 1-2 | Umbraco 17 LTS på .NET 10, SQLite til lokal dev. Solution, projektreferencer, build og test verificeret. Flad mappestruktur (alle projekter i repo-roden, ingen `src/`+`tests/`-opdeling) er bekræftet beslutning — kickoff-planen er opdateret til at afspejle dette. |
| TASK-02 | Høj | CRM-integrationslag isoleret bag interface, med midlertidig mock | Færdig | Uge 1-2 | `ICrmClient` (`GetCustomerProfile`, `GetSubscriptions`, `GetInvoices`) er implementeret i `MockCrmClient` med 3 eksempelkunder (2x B2C, 1x B2B, heriblandt et abonnement i binding), og dækket af 10 unit-tests. Rigtig implementering tilføjes senere som ny klasse bag samme interface. |
| TASK-03 | Mellem | Docker-opsætning (dev + prod compose) | Ikke startet | Uge 1-2 | `docker-compose.dev.yml` og `docker-compose.prod.yml` i `/docker`, jf. kickoff-planens TASK-03. Dev-filen er kun til verificeringskørsler før merge til `develop` (ikke daglig brug), prod skal hærdes (persistent storage, sikkerhedskonfig, ingen default credentials). |
| TASK-04 | Mellem | Backlog og versioneret git pre-push-hook | Færdig | Uge 1-2 | `docs/BACKLOG.md` (denne fil) + `.githooks/pre-push` (advarer, blokerer ikke, ved kodeændringer uden BACKLOG-opdatering) + opsætningsinstruktion i README (`git config core.hooksPath .githooks`). Hook testet reelt: advarer korrekt ved kodeændring uden backlog-opdatering, tier korrekt når backloggen opdateres i samme push. |
| TASK-05 | Høj | Automatiseret test-workflow ved push/PR | Færdig | Uge 1-2 | `.github/workflows/test.yml` kører `dotnet restore`/`build`/`test` (Release) på `MyCMSSolution.slnx` ved push til `main`/`develop` og ved pull request mod disse branches, på `ubuntu-latest` med .NET 10 SDK. Fejl i build eller test giver automatisk rødt kryds i GitHub, da `dotnet test` returnerer non-zero exit code. Verificeret lokalt i Release-konfiguration (build + alle 10 tests grønne) før push. |

Vurderer arkitekturoverholdelse, sikkerhed (særligt autentificering/CRM-kald), ubegrundede afvigelser fra kickoff-planen, samt manglende fejlhåndtering/tests. Retter ikke selv — rapporterer kun fund, prioriteret efter alvorlighed. Jf. kickoff-planens TASK-06. |
